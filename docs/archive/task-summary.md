# LUTCalc 中文化重制项目任务摘要

## 一、项目目标

本项目的核心目标是克隆并重制开源 [LUTCalc](https://cameramanben.github.io/LUTCalc/LUTCalc/index.html) 计算器，在保留原版 LUT 计算、预览、生成和导出能力的基础上，建立一个完整中文化、可主题化、可维护的现代 Web 工作台。

项目始终遵循以下原则：

1. **核心计算功能保持与原版一致**。原版 LUTCalc 计算引擎继续保留，并通过同源隐藏 iframe 驱动。
2. **可见界面逐步迁移为 React 原生实现**。旧版 iframe 不再承担主界面展示，只保留为兼容计算、预览、导出和参数同步引擎。
3. **用户可见术语全部中文化**。相机、伽马、色域、LUT、调整项、流程、曲线配置等界面内容统一使用简体中文。
4. **视觉系统支持内置主题和明暗模式**。主题以标准 JSON 配置维护，不允许临时上传主题，避免刷新后丢失。
5. **最终布局回归原版 LUTCalc 的信息密度和层级关系**，而不是停留在现代卡片式 UI 的表面仿制。

## 二、技术基础

项目采用 React 19、Vite、TypeScript、Tailwind CSS 4 与 shadcn/ui 组件体系，作为静态前端项目运行。项目路径为 `/home/ubuntu/lutcalc-redesign`，线上域名为 [lutcalcapp-s8bmtac7.manus.space](https://lutcalcapp-s8bmtac7.manus.space)。

核心代码遵循 BSD Allman 大括号风格，并在主要桥接和架构代码中加入中文注释。主工作台位于 `client/src/pages/Home.tsx`，原生调整项位于 `client/src/components/NativeAdjustments.tsx`，主题注册位于 `client/src/themes/themeRegistry.ts`，全局界面样式位于 `client/src/index.css`。

## 三、主要功能演进

### 1. 原版引擎克隆与 iframe 桥接

最初保留原版 LUTCalc 作为独立计算器，并将其嵌入 React 工作台。之后逐步隐藏原版可见参数界面，仅保留同源 iframe 作为计算引擎。

父页面通过 DOM 查询、事件派发和状态轮询，控制原版引擎中的相机、伽马、色域、LUT 输出、调整项和生成操作。由于 iframe 与父页面同源，系统可以读取原版控件状态、动态选项和曲线画布。

对于 LUT 分析功能，项目额外桥接了原版 `LUTAnalyst` 的 `gotFile`、`doStuff` 和 `doneStuff` 原型方法，并增加父页面消息通知、动态选项同步和状态快照轮询，从而修复“LUT 已分析但主预览没有变化”的问题。

### 2. React 原生参数卡

主界面的相机输入、色彩管线、LUT 输出、调整项和曲线预览均迁移为 React 原生组件。界面直接读取隐藏引擎的选项和当前值，用户操作再同步回引擎。

当前主布局按原版信息结构排列：

| 模块 | 当前布局 | 主要内容 |
|---|---|---|
| 01 相机输入 | 上方左侧 | 相机品牌、型号、原生 ISO、CineEI ISO、挡位修正 |
| 02 色彩管线 | 上方右侧 | 记录伽马、记录色域、输出伽马、输出色域 |
| 03 LUT 输出 | 第二行全宽 | LUT 标题、输出格式、硬裁切、预览和生成按钮 |
| 04 调整项 | 第三行全宽 | 原版连续调整项列表和 LUT 解析 |
| 05 曲线预览 | 下方全宽 | 原始引擎实时生成的 LUT 曲线 |

### 3. 调整项重构

调整项经历了从 iframe CSS 覆盖到 React 原生重建的过程。最终版本不再使用独立浮动小卡片，而是回归原版 LUTCalc 的连续纵向条带结构。

调整项标题区包括：

- 红色编号块“04”；
- “调整项”标题和说明；
- 右侧“启用调整项”总开关。

每个子模块均采用前置选择框、条目标题和右侧状态文字。启用模块后，内部参数区域直接在该条目下方展开，不另起独立卡片。

当前包含的调整模块有：

- 白平衡；
- PSST-CDL；
- ASC-CDL；
- 多色调；
- 高光色域；
- 膝点；
- 黑电平 / 高光电平；
- 黑伽马；
- 显示色彩空间转换；
- 色域限制；
- 伪色；
- LUT 解析。

当前默认状态为：总调整项开关启用，常规子调整项默认勾选，白平衡默认展开，LUT 解析作为列表末尾的同级条目保留独立开关。

### 4. 白平衡原版布局

根据用户提供的原版截图，白平衡区域已从占位说明改为原版式参数区，包含：

- 参考白输入，默认 5500 K；
- 新白平衡输入，默认 5500 K；
- “从新白平衡解锁光源”按钮；
- CTO / CTB 水平滑块；
- Minus Green / Plus Green 水平滑块；
- 两组滑块各自的清除和重置按钮。

控件采用原版的紧凑纵向顺序、浅灰色实体滑块面板和中间 Reset 控件布局。

### 5. LUT 解析

LUT 解析最初位于原版调整项中，后来曾被错误地放入工具侧栏，之后已重新移回调整项列表末尾。

当前 LUT 解析区域包括：

- 前置选择框；
- “导入新 LUT / 读取已分析 LUT”分析方式；
- LUT 文件选择；
- 文件名状态显示；
- 分析 LUT；
- 重置；
- 选择文件按钮。

导入和分析动作会驱动隐藏原版引擎，并通过异步桥接刷新父页面的伽马状态、LUT 标题和曲线预览。

## 四、工作流程与曲线配置

### 1. 工作流程记录

项目增加了工作流程功能，用于记录用户对参数的修改并保存为可重复执行的流程。流程支持：

- 自定义流程名称；
- 开始记录和停止记录；
- 保存流程；
- 导出 JSON 文件；
- 导入 JSON 文件；
- 清空当前流程；
- 执行已保存流程。

流程回放开始时会自动停止录制，避免回放动作再次被录入当前流程。流程数据存储在浏览器本地存储中，不依赖后端数据库。

### 2. Log / Gamma 配置

项目定义了标准化的 `lutcalc-log-gamma-profile` JSON 配置格式，支持：

- 日志或伽马类型；
- 采样点曲线；
- 编码和解码公式；
- 输入色域；
- 数据范围和位深；
- 色彩空间元数据；
- 中灰 IRE；
- 来源和作者信息。

配置文件可以在工具中心独立导入、保存和导出。目前配置不会自动注册到原版 LUTCalc 引擎中，仍保留为独立的开发者扩展机制。

## 五、L-Log 独立交付物

根据用户提供的 Leica L-Log Reference Manual，项目完成了独立 L-Log 配置文件和操作说明。该配置文件没有注册到主程序中，也没有改变原版 LUTCalc 的内置选项，符合“作为独立下载文件提供”的要求。

同时完成了 Leica LG1056 字体处理：将用户提供的字体转换为 WOFF2，并以 data URI 形式内嵌到 Leica 主题配置中。浏览器端已验证字体能够在父页面和同源调整项 iframe 中加载。

## 六、主题系统

项目建立了 JSON 驱动的内置主题系统，当前包含：

- Ubuntu；
- KDE；
- macOS；
- Omarchy；
- Leica 固件；
- Lumix 固件。

主题系统支持：

- 主题选择；
- 明暗模式切换；
- 主题本地持久化；
- 主题颜色令牌注入；
- 主题字体注入；
- 主题圆角、阴影、控件和预览混合模式配置。

Ubuntu 是当前默认主题，使用 Ubuntu 字体、Ubuntu 橙强调色和深紫色标题栏。Leica 主题使用内嵌 LG1056 字体；Lumix 主题参考 Panasonic Lumix 固件界面。

## 七、界面布局回归过程

项目曾经历几轮视觉方向调整：

1. 胶片实验室 / 新粗野主义方向；
2. GNOME / Ubuntu 风格；
3. Apple 风格；
4. 现代化 React 参数卡；
5. 用户指出界面与原版割裂后，重新参考 LUTCalc 原版页面；
6. 当前回归原版信息密度、模块排列和连续条带布局。

最终确认的回归原则是：

> 保留主题系统和中文化，但不再用现代仪表盘式卡片替代原版 LUTCalc 的实际布局层级。

因此当前版本降低了卡片圆角、间距、留白和阴影，并恢复原版的密集排列、全宽区域、连续调整项和条目内展开结构。

## 八、曲线预览与主题兼容

曲线预览从原始引擎画布实时合成，显示输入和输出曲线。为避免深色模式下曲线不可读，预览区域始终强制使用不透明白底，并关闭混合模式反转。

该规则适用于所有主题和明暗模式：

- 预览背景固定为白色；
- 曲线图像不使用 `multiply` 混合；
- 深色主题不会反转曲线预览；
- LUT 分析完成后通过异步同步刷新曲线。

## 结论

本项目已经从“将原版计算器嵌入现代页面”逐步发展为“保留原版计算核心、使用 React 管理可见界面、完整中文化、支持主题、工作流程和独立配置文件，并最终回归原版布局逻辑”的 LUTCalc 中文重制版。

当前版本的重点不再是追求与原版完全不同的现代视觉，而是让新的 React 界面在功能、层级、密度和操作方式上重新接近 LUTCalc 原版，同时保留现代前端所需的主题、响应式和可维护性。
