# LUTCalc 中文重制项目任务简报

你需要从零开始，或基于现有开源 LUTCalc 代码，制作一个功能保持一致、界面中文化、支持主题切换的 LUTCalc Web 重制版。

## 一、项目目标

请重制开源 LUTCalc 计算器：

参考原版页面：

- https://cameramanben.github.io/LUTCalc/LUTCalc/index.html

核心要求是：**保留原版 LUT 计算引擎和功能逻辑，但将可见界面改为简体中文，并重新实现前端布局、主题和交互。**

不要只做一个外层包装页面，也不要简单把原版 iframe 放在页面里。最终用户看到的主界面应该是你实现的原生 Web 界面；原版代码可以作为隐藏的同源计算引擎，通过 DOM、事件和状态桥接驱动。

## 二、必须保留的核心功能

以下功能必须保持与原版 LUTCalc 一致或兼容：

1. 相机品牌和相机型号选择。
2. 原生 ISO、CineEI ISO 和挡位修正。
3. 记录伽马、记录色域、输出伽马、输出色域。
4. LUT 标题 / 文件名设置。
5. LUT 输出格式选择。
6. 硬裁切模式选择。
7. 更新预览。
8. 生成 LUT。
9. 生成 LUT 套装。
10. 各类调整项启用、关闭、展开和折叠。
11. LUT 文件导入与 LUT 分析。
12. 曲线预览。
13. 原版计算引擎的异步更新逻辑。

如果使用 iframe 保留原版计算引擎，必须隐藏原版可见 UI，只保留计算、预览、导出和兼容桥接能力，禁止出现“双重界面”或 iframe 套娃。

## 三、整体布局要求

界面布局必须参考原版 LUTCalc，而不是采用普通 SaaS 仪表盘或现代卡片墙设计。

### 桌面端布局

按照以下顺序组织页面：

```text
顶部标题栏

01 相机输入              02 色彩管线

03 LUT 输出（全宽）

04 调整项（全宽，连续纵向列表）

05 曲线预览（全宽，白色背景）
```

01 和 02 位于同一行，03、04、05 各自占满主工作区宽度。卡片之间的间距要紧凑，避免大面积留白。模块应使用低圆角、细边框和清晰的标题层级。

### 调整项布局

调整项必须采用原版连续条带结构，而不是四列网格或大量悬浮小卡片。

标题区包括：

- 左侧红色编号块“04”；
- 标题“调整项”；
- 一行说明文字；
- 右侧勾选框“启用调整项”。

条目从上到下连续排列，每个条目使用整行边框和细分隔线。启用后，参数区域直接在对应条目下方展开，不要跳出成独立卡片。

## 四、默认状态

页面初次加载时：

1. “启用调整项”总开关默认勾选。
2. 常规调整项默认启用，至少应显示为已启用状态。
3. 白平衡默认展开，便于用户立即看到原版参数布局。
4. LUT 解析作为调整项列表的最后一个同级条目，不要放到侧边栏。
5. 曲线预览始终显示白色背景，无论当前是浅色还是深色主题。

## 五、白平衡模块

白平衡区域必须参考以下原版结构：

```text
White Balance / 白平衡复选框

Reference White / 参考白       5500 K
New White Balance / 新白平衡    5500 K

Unlock Lightsource From New White
从新白平衡解锁光源

[水平滑块]                         CTO -------- CTB
                       Clear / 清除   Reset / 重置

[水平滑块]              Minus Green -------- Plus Green
                       Clear / 清除   Reset / 重置
```

原版白平衡截图中，滑块区域使用浅灰色实体面板，滑块水平排列，两端是对应色彩偏移方向，中间是 Clear 和 Reset 操作。不要把白平衡做成普通表单字段堆叠。

## 六、LUT 解析

LUT 解析必须是“调整项”下方的最后一个同级条目，并支持：

1. 前置选择框。
2. 导入新 LUT。
3. 读取已分析 LUT。
4. 选择 `.cube`、`.3dl`、`.lut` 等文件。
5. 显示当前文件名。
6. 分析 LUT。
7. 重置。
8. 分析完成后刷新输出伽马、LUT 标题和曲线预览。

重点修复一个常见问题：文件已经上传并完成分析，但主页面的预览曲线没有变化。必须监听原版分析器的真实完成阶段，或者通过同源原型桥接、父页面消息和状态轮询确保最终刷新。

## 七、中文化要求

所有用户可见文字使用简体中文，包括：

- 标题；
- 字段名；
- 按钮；
- 状态文本；
- 错误提示；
- LUT 分析操作；
- 工作流程操作；
- 主题设置；
- 版权说明。

技术格式、相机型号、伽马名称、色域名称和文件扩展名可以保留行业惯用英文，例如 `S-Log3`、`V-Log`、`ARRI Wide Gamut`、`.cube`，但周围说明文字必须中文。

## 八、主题系统

实现一个 JSON 驱动的内置主题系统，不支持临时主题上传。

至少提供以下内置主题：

- Ubuntu；
- KDE；
- macOS；
- Omarchy；
- Leica 固件；
- Lumix 固件。

主题配置至少应包含：

```json
{
  "id": "ubuntu",
  "name": "Ubuntu",
  "font": "Ubuntu, Noto Sans SC, sans-serif",
  "light": {
    "canvas": "#deddda",
    "surface": "#f7f7f7",
    "card": "#ffffff",
    "text": "#242424",
    "muted": "#6b6b6b",
    "border": "#d6d6d6",
    "accent": "#e95420",
    "topbar": "#2c001e"
  },
  "dark": {
    "canvas": "...",
    "surface": "...",
    "card": "...",
    "text": "...",
    "muted": "...",
    "border": "...",
    "accent": "...",
    "topbar": "..."
  }
}
```

要求：

1. 支持明暗模式切换。
2. 主题和模式保存到 localStorage。
3. 所有可见控件都使用主题变量。
4. 深色模式不能破坏输入框、复选框、调整项和曲线预览的可读性。
5. 曲线预览例外：永远使用不透明白底。
6. Leica 主题可以内嵌用户提供的 Leica LG1056 字体，但字体必须作为网页字体加载，不能只写一个未验证的字体名称。

## 九、工作流程功能

增加“工作流程”工具，用于记录用户的参数操作并保存为可重复执行的文件。

功能包括：

- 流程名称；
- 开始记录；
- 停止记录；
- 保存流程；
- 导入流程 JSON；
- 导出流程 JSON；
- 清空当前流程；
- 执行已保存流程。

重要规则：执行流程时必须自动停止录制，避免流程回放被再次记录。

流程记录格式建议：

```json
{
  "version": 1,
  "name": "流程名称",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "events": [
    {
      "action": "change",
      "selector": "#some-control",
      "value": "some-value",
      "label": "参数名称"
    }
  ]
}
```

## 十、Log / Gamma 配置文件

设计一个独立 JSON 配置格式，用于支持个人开发者自制的 Log、Gamma 和色域配置。

配置至少支持：

- 配置 ID；
- 名称；
- `log` 或 `gamma` 类型；
- 采样曲线；
- 编码公式；
- 解码公式；
- 输入色域；
- 数据范围；
- 位深；
- 色彩空间元数据；
- 中灰 IRE；
- 作者和来源。

推荐格式：

```json
{
  "schema": "lutcalc-log-gamma-profile",
  "version": 1,
  "id": "example-log",
  "name": "Example Log",
  "kind": "log",
  "author": "作者",
  "description": "配置说明",
  "input": {
    "gamut": "Example Gamut",
    "range": "full",
    "bitDepth": 10
  },
  "curve": {
    "type": "samples",
    "samples": [
      { "input": 0, "output": 0 },
      { "input": 0.18, "output": 0.42 },
      { "input": 1, "output": 1 }
    ]
  },
  "metadata": {
    "middleGrayIRE": 42,
    "source": "来源说明"
  }
}
```

第一阶段可以只支持导入、校验、保存和导出；如果要真正接入 LUTCalc 选项，必须增加曲线引擎适配层，不能只把配置显示在列表里。

## 十一、L-Log 独立文件

如果用户提供 Leica L-Log 白皮书或参考手册，需要：

1. 阅读并提取曲线、色域、中灰和参数规则。
2. 生成独立的 L-Log JSON 配置文件。
3. 生成使用说明。
4. 提供下载。
5. 不要默认把 L-Log 内置到主程序选项里，除非用户明确要求。

## 十三、代码风格

代码要求：

1. 使用 BSD Allman 风格，大括号放在新行。
2. 核心逻辑加入准确中文注释。
3. React 组件拆分清晰。
4. 主题令牌集中管理，避免到处硬编码颜色。
5. 不重复实现已经存在的通用控件。
6. 保留隐藏引擎桥接的边界说明。
7. 不使用多个互相覆盖的 iframe 界面。
8. 不使用纯占位 UI 代替核心功能。

## 十四、验收标准

完成后必须逐项验证：

### 功能验收

- 相机、伽马、色域和 LUT 输出控件能够驱动原版引擎。
- 修改参数后曲线预览会刷新。
- LUT 导入和分析完成后曲线预览会发生实际变化。
- 调整项开关能同步到引擎。
- 白平衡默认启用并展开。
- LUT 解析位于调整项列表末尾。
- 生成 LUT 和生成套装能够触发原版导出逻辑。
- 工作流程可以记录、保存、导入、导出和回放。
- 回放时自动停止录制。

### 视觉验收

- 01/02 双栏布局正确。
- 03/04/05 全宽排列正确。
- 调整项是连续列表，不是四列网格。
- 白平衡布局接近原版截图。
- 深色模式下所有文字和控件可读。
- 曲线预览永远白底。
- 移动端无横向溢出、按钮隐藏或条目重叠。
- 不出现旧版 iframe 套娃或重复标题栏。

### 工程验收

- TypeScript 检查通过。
- 生产构建通过。
- 至少完成桌面端和移动端截图回归。
- 重要版本保存 checkpoint 或 Git 提交。
- 在交付说明中列出已完成事项、已知限制和后续建议。

## 十五、实现顺序建议

请按以下顺序执行，不要一开始就只做视觉装饰：

1. 获取并分析原版 LUTCalc 源码和 DOM 结构。
2. 确认许可证和核心计算入口。
3. 搭建 React + TypeScript 主工作台。
4. 接入隐藏原版引擎并实现状态桥接。
5. 先实现 01、02、03 参数控件。
6. 实现 04 调整项连续列表和默认启用逻辑。
7. 实现白平衡原版参数区。
8. 将 LUT 解析放回调整项列表末尾。
9. 实现 05 曲线预览并固定白底。
10. 增加工作流程和配置文件功能。
11. 增加内置主题系统。
12. 完成桌面端、移动端、深色模式和 LUT 分析回归。
13. 最后再做字体、阴影、圆角和动效等视觉微调。

最终应交付：

1. 可运行的 LUTCalc 中文 Web 应用。

3. 原版密集布局的 React 主界面。

5. 工作流程记录、导入、导出和回放。
6. 独立 Log/Gamma 配置文件机制。
7. 独立 L-Log 配置文件和使用说明。
8. 项目 README、构建方式、许可证说明和已知限制。
