# LUTCalc 中文工作台用户操作与自定义曲线手册

> **适用对象**：需要建立相机 Log/Gamut 转换、生成 LUT、分析已有 LUT，或整理个人色彩曲线资料的用户。
>
> **重要提示**：本工作台使用原版 LUTCalc 作为计算与导出核心。界面已经中文化，但色彩空间、范围和插值的选择仍会直接影响结果。正式交付前，请始终在目标设备、目标监看环境和真实素材上复核。

| 功能区 | 用途 |
|---|---|
| 01 相机输入 | 选择相机、型号、CineEI ISO 与挡位修正 |
| 02 色彩管线 | 定义记录 Gamma/Gamut 与输出 Gamma/Gamut |
| 03 LUT 输出 | 选择 1D/3D、网格、范围、用途、格式与裁切 |
| 04 调整项 | 启用白平衡、CDL、黑伽马等调整，或打开 LUT 解析器 |
| 05 原版预览与曲线 | 查看原版 Canvas 预览、范围、WFM、Vector、RGB Parade 与曲线 |
| 左侧工具中心 | 录制/执行流程，以及导入/管理自定义曲线配置 |

## 1. 开始前的基本原则

LUT 是一个确定性的输入—输出映射。要得到可复现的结果，必须同时固定记录 Gamma、记录 Gamut、输入范围、输出 Gamma、输出 Gamut、LUT 网格、插值方式和裁切选项。仅凭“看起来像某相机的 Log”选择 Gamma，可能造成中灰、饱和度和高光错误。

> **先确认输入，后做调整。** 应先在 01/02 区确认素材基底，再启用白平衡、CDL、黑伽马等调整。若输入基底不正确，后续微调不具有可迁移性。

## 2. 首次使用：建立一条标准转换

### 2.1 选择相机输入

在 **01 相机输入** 中选择相机品牌与型号。引擎连接后，下拉菜单来自原版 LUTCalc 的实际目录，而不是工作台手写的简化列表。根据拍摄设置填写 CineEI ISO 和挡位修正；不确定时应先维持相机实际拍摄值。

### 2.2 定义记录与输出色彩管线

在 **02 色彩管线** 先设置“记录设置”，再设置“输出设置”。常见的 Rec.709 交付流程是以拍摄 Log/Gamut 作为记录设置，以 Rec.709 Gamma/Gamut 作为输出设置；HDR 或广色域流程则应选择对应的输出目标。

| 设置项 | 作用 | 使用建议 |
|---|---|---|
| 记录 Gamma | 定义输入亮度编码 | 必须与相机或素材元数据一致 |
| 记录 Gamut | 定义输入色度基准 | 与 Gamma 同时确认，避免跨品牌误配 |
| 输出 Gamma | 定义目标亮度曲线 | 按监看/交付规范选择 |
| 输出 Gamut | 定义目标色域 | 先确认 Rec.709、P3、Rec.2020 等目标 |

### 2.3 配置 LUT 输出

在 **03 LUT 输出** 中设置标题、类型、网格和范围。标题会用于原版生成器的命名链路；正式交付时应使用能标识项目、输入、输出和版本的名称，例如 `A-Cam_FLog2_to_Rec709_v01`。

| 选项 | 含义 | 推荐场景 |
|---|---|---|
| 1D LUT | 仅处理亮度/单通道映射 | 技术 Gamma 转换、需要小文件时 |
| 3D LUT | 同时处理亮度和颜色 | 大多数创意 LUT、相机显示 LUT、色彩空间转换 |
| 17³ / 33³ / 65³ | 3D 网格密度 | 17³ 用于预览；33³ 常用；65³ 用于复杂色彩变化和高要求交付 |
| 100% 输入/输出 | 视频合法范围 | 广播/视频规范管线 |
| 109% 输入/输出 | 保留超白编码空间 | 需要保留高光扩展的管线 |
| 调色 LUT | 常规后期工作流 | DaVinci Resolve、Premiere 等调色环境 |
| 相机/监看 LUT（MLUT） | 相机或监看侧使用 | 先核对相机对格式和网格的限制 |

勾选 **0%–100%** 或选择 **硬裁切** 会改变端点行为。若高光出现意外断层或白点不一致，应首先核对范围、裁切和相机端 LUT 规范，而不是立即增加对比度或黑伽马补偿。

### 2.4 生成 LUT

完成 01–03 后，点击 **生成 LUT**。生成由原版引擎执行，浏览器会下载文件；点击 **生成套装** 则使用原版的套装导出路径。生成之前可先点击“显示原版预览”，在 05 区检查曲线与画面。

## 3. 调整项的使用

在 **04 调整项** 顶部保持“启用调整项”开启。普通调整项由左侧复选框控制：未勾选时不向引擎启用该模块；勾选后参数区直接出现。LUT 解析器是独立工具条，不需要普通模块复选框。

### 3.1 推荐调整顺序

建议先使用白平衡，再使用曝光/对比度/饱和度一类整体调整，最后使用黑伽马、膝点、高光色域和色域限制等局部工具。每启用一个模块，都应回到 05 区查看曲线和预览变化。

| 模块 | 适用问题 | 注意事项 |
|---|---|---|
| 白平衡 | 色温与绿/洋红偏移 | 先确认输入 Gamma/Gamut 正确 |
| PSST-CDL / ASC-CDL | 曝光、对比度、色相、饱和度 | 小步调整；多个 CDL 模块叠加会提高排查难度 |
| 多色调 | 阴影、中间调、高光的创意色彩倾向 | 属于创意调整，不应替代输入基底校正 |
| 黑电平/高光电平、膝点 | 黑位、高光压缩、映射端点 | 与 100%/109% 范围和硬裁切共同影响结果 |
| 黑伽马 | 阴影层次与过渡 | 过强会引入暗部噪点感或不自然的抬黑 |
| 色域限制 | 输出色域压缩 | 应在目标显示色域明确后使用 |

使用每个模块底部的 **重置本模块** 可以恢复该模块的初始控件值。工作台会把普通参数变化同步给兼容引擎；如果某种复杂原版参数未表现如预期，应先关闭模块、确认曲线变化，再重新启用。

## 4. 分析已有 LUT

LUT 解析器用于读取已有 LUT，并由原版 **LUTAnalyst** 估计其传递函数和色彩空间。它不是“把任何 LUT 无损反编译为原始工程文件”的工具；分析结果依赖文件内容、范围、网格、插值和所选输入基底。[1]

### 4.1 标准分析步骤

1. 在 04 区末尾展开 **LUT 解析**。
2. 点击 **选择文件**，或直接在“LUT 文件”输入框选择 `.cube`、`.3dl`、`.lut` 或 `.txt` 文件。
3. 阅读文件状态、兼容性提示和元数据区。若出现“文件可能截断”“未声明网格”或“非 RGB 三元组”等诊断，应先获取正确的原始文件。
4. 核对 **输入 Gamma** 与 **输入 Gamut**。文件头含 F-Log2/F-Log2C 或 F-GamutC 线索时，系统会尝试匹配 Fujifilm F-Log2 / F-Log Gamut；仍须由用户确认真实来源。
5. 设置分析维度（33³ 或 65³）、方法和 LUT 范围。
6. 点击 **分析 LUT 并应用当前输出**。
7. 等待状态从“正在分析”变为“分析结果已同步”。此时输出管线应出现同名 `LA - 标题` Gamma 和 Gamut，曲线预览也会更新。

### 4.2 如何阅读分析信息

分析面板会尽量显示文件原始标题、机型、原始 Gamma/Gamut、网格、SHA-256 前缀、引擎映射和诊断信息。原始元数据与引擎映射必须区分：例如文件可能标为 `F-Log2C`，而原版可选项为 `Fujifilm F-Log2`；这是工作台显示的标准选项映射，并不自动宣称二者严格等价。

分析成功后，工作台显示：

| 信息 | 含义 |
|---|---|
| 当前输出 | 已由原版注册的 `LA - 标题` Gamma/Gamut 对 |
| 分析参数 | 当前选用的维度、插值方式、范围 |
| 起点/中点/终点 | 原版传递函数缓冲区的 IRE 与 10-bit 摘要 |
| 完成时间 | 工作台确认 LA 输出成对注册的时间 |

如果点击分析后仍显示默认输出或没有 `LA -` 成对结果，不要继续生成 LUT。应检查文件是否损坏、输入 Gamma/Gamut 是否匹配、范围是否选错，并重新选择文件后分析。

### 4.3 范围与插值如何选择

**LUT 范围** 左侧是文件输入编码范围，右侧是分析后的显示输出范围。100% 通常表示视频合法范围，109% 保留超白。范围选择不正确时，白点、高光裁切、灰阶位置和波形读数都会改变。

| 选项 | 适用理解 |
|---|---|
| 109%→100% | 输入保留扩展，输出约束到合法显示范围 |
| 109%→109% | 输入与输出都保留扩展范围 |
| 100%→100% | 标准合法范围路径 |
| 100%→109% | 从合法输入扩展到输出编码空间；仅在目标链路明确需要时使用 |

分析方法中的“三线性”速度较快，“四面体”常用于更平滑的 3D 插值，“三次插值（Tricubic）”适用于需要更高阶插值的情况。实际选择应受目标应用、网格大小和原始 LUT 特性约束；改变插值后，应重新检查高饱和颜色和极端高光/阴影。

## 5. 原版预览与曲线

05 区显示的是原版 Canvas 快照。点击 **显示原版预览** 后，可切换小图/大图，选择高对比度、低对比度、Rec.709、xy/uv 色度图或灰度预设，并选择 100%/109% 预览范围。

勾选 **WFM**、**Vector**、**RGB** 后，工作台会展示原版波形、矢量示波和 RGB Parade 快照。曲线区域固定为白底，目的是让亮/暗主题下的曲线都保持可读。原版预览图像加载会要求确认图像 Gamma、色彩空间和范围；不要把未知图片直接按 Rec.709 解释。

## 6. 使用流程记录提高重复性

左侧 **工具中心 → 流程** 允许记录对兼容引擎的参数操作。它适用于将一组重复的相机/管线/调整步骤保存为模板。

1. 输入流程名称。
2. 点击 **开始记录**。
3. 在主工作台进行参数选择与调整。
4. 点击 **停止记录**，确认步骤数。
5. 点击 **保存流程**；该流程会保存到当前浏览器。
6. 可点击 **执行** 回放，或点击 **导出** 保存为 `.lut流程.json`。

> 回放流程开始时，系统会自动停止记录，避免把回放动作重新写入流程。流程依赖控件选择器和原版 DOM 结构；跨重大版本、跨不同原版资源或缺失某一选项时，个别步骤可能被跳过。

导入流程时，选择之前导出的 JSON。导入只检查名称与事件数组，不会验证该流程是否适合当前相机或当前 LUT；请先检查 01/02 的输入设置。

已保存流程支持 **执行 / 导出 / 重命名 / 删除 / 上移 / 下移**，重命名按回车提交、按 Esc 取消；已导入的自定义曲线配置同样支持这些操作。

### 6.1 文件步骤：重新选择或固定文件

流程中的「导入新的 LUT / 加载已分析的 LA LUT」文件步骤默认是 **重新选择** 模式：回放时会打开系统文件选择框，由你手动挑选对应 LUT 文件后继续。这是为了让流程可以跨机器复用——录制时的本地路径（`C:\fakepath\...`）不应当被当作真实文件路径回放。

如果你需要在无人值守时复用（例如调试、自动化），可以在导出的流程 JSON 中给该步骤增加 `filePath` 字段指定固定文件，回放时直接载入、不再弹框：

```json
{
  "action": "change",
  "selector": "[data-lutcalc-workflow-id=\"lc-0765\"]",
  "label": "导入新的 LUT加载已分析的 LA LUT",
  "value": "C:\\fakepath\\FLog2_to_CLASSIC-Neg._65grid_V.1.00.cube",
  "filePath": "/FLog2_to_CLASSIC-Neg._65grid_V.1.00.cube"
}
```

- 离线桌面版：`filePath` 写宿主机绝对路径，例如 `/home/user/LUT/FLog2_to_CLASSIC-Neg._65grid_V.1.00.cube`。
- 网页版：先把文件放进站点可访问目录（如 `client/public/`），`filePath` 写站点相对路径，例如 `/FLog2_to_CLASSIC-Neg._65grid_V.1.00.cube`。
- 不加 `filePath` 即回到默认的「重新选择」模式。

## 7. 主题与本地数据

右上角可选择 Ubuntu、KDE、macOS、Omarchy，并可切换亮/暗模式。主题仅改变视觉令牌，不改变计算、LUT 分析或导出数学。主题与模式保存于浏览器本地；已移除的旧主题偏好会回退到 Ubuntu。

流程记录和自定义曲线配置也保存在浏览器 `localStorage`。清理浏览器站点数据、使用隐身窗口或更换浏览器后，未导出的内容可能不再存在。对于重要配置，请及时导出 JSON 备份。

## 8. 自定义色彩曲线配置

### 8.1 当前功能边界

工具中心的 **曲线** 标签页用于导入、保存、导出和管理 Log/Gamma 配置文件。它适合保存个人曲线说明、白皮书数据或与团队交换结构化资料。

> **引擎注册**：带 `curve.engineParams`（9 个 `LUTGammaLog` 参数）的公式型配置导入后会自动注册到原版引擎，出现在 02 区的记录 Gamma、输出 Gamma 以及 LUT 分析的“输入 Gamma”下拉中，可直接参与 LUT 生成与分析。未提供 `engineParams` 的采样型配置仅作为资料库保存，不进入引擎下拉。

### 8.2 文件格式

配置文件必须是 JSON，并具有以下基本字段：

```json
{
  "schema": "lutcalc-log-gamma-profile",
  "version": 2,
  "id": "my-log-v1",
  "name": "我的 Log 曲线 v1",
  "brand": "我的相机",
  "displayName": "Log v1",
  "kind": "log",
  "author": "作者或团队",
  "description": "适用相机、版本和注意事项",
  "input": {
    "gamut": "自定义色域名称",
    "range": "full",
    "bitDepth": 10
  },
  "curve": {
    "type": "samples",
    "samples": [
      { "input": 0.0, "output": 0.0 },
      { "input": 0.18, "output": 0.42 },
      { "input": 1.0, "output": 1.0 }
    ]
  },
  "colorSpace": {
    "primaries": "可选：色度坐标或标准名称",
    "whitePoint": "D65"
  },
  "metadata": {
    "middleGrayIRE": 42,
    "source": "白皮书或测量记录"
  }
}
```

`schema` 必须为 `lutcalc-log-gamma-profile`，`version` 必须为 `2`，并且 `id`、`name`、`brand`、`displayName`、`kind`、`curve` 不可缺失。`kind` 只能是 `log` 或 `gamma`；`brand` 用于下拉分组，`displayName` 用于下拉与“标题 *”映射展示。

### 8.3 采样表曲线

`curve.type` 为 `samples` 时，`samples` 至少需要两个采样点，每个点具有数值型 `input` 与 `output`。建议按输入从小到大排列，明确输入/输出是归一化线性值、场景值、编码值还是 IRE；这些单位约定应写在 `description` 或 `metadata.source` 中。

| 建议 | 原因 |
|---|---|
| 覆盖 0、18% 灰、90%/100% 等关键位置 | 便于检查黑位、中灰和高光 |
| 增加拐点附近采样密度 | 减少插值时的不确定性 |
| 不要用非递增输入点 | 会使后续适配或插值难以解释 |
| 写明测量基准与范围 | 10-bit full、legal、IRE 与归一化值不能混用 |
| 保留来源 | 便于将来复核白皮书、实验记录或固件版本 |

### 8.4 公式曲线

`curve.type` 为 `formula` 时，至少提供 `encode` 或 `decode` 之一；推荐同时提供两者，并在 `description` 中说明变量定义、对数底、常量、分段边界、有效域和裁切策略。当前导入校验会验证字段存在，但不会执行、验证或拟合公式。

```json
{
  "schema": "lutcalc-log-gamma-profile",
  "version": 2,
  "id": "my-gamma-formula-v1",
  "name": "我的公式曲线 v1",
  "brand": "我的相机",
  "displayName": "公式曲线 v1",
  "kind": "gamma",
  "curve": {
    "type": "formula",
    "encode": "按白皮书填写编码公式及分段条件",
    "decode": "按白皮书填写解码公式及分段条件",
    "engineParams": "可选：9 个 LUTGammaLog 参数 [b, c, d, e, f, g, h, i, j]；提供后自动注册到引擎 Gamma 下拉"
  },
  "metadata": {
    "source": "文档名称、版本、页码或测量方法"
  }
}
```

### 8.5 导入、校验与备份

进入 **工具中心 → 曲线**，点击 **导入配置** 并选择 JSON。导入成功后会显示曲线名称、类型及采样点数；带 `engineParams` 的配置会同步注册到引擎下拉。可点击 **导出** 保存副本，或点击 **删除** 移除本地条目。出现“配置文件无效”时，优先检查 schema、version（v2）、id、name、brand、displayName、kind、curve.type 与 samples 数量。

## 9. 常见问题

| 问题 | 建议处理 |
|---|---|
| 导入曲线配置后为什么不在 Gamma 下拉中出现？ | 只有带 `curve.engineParams` 的公式型配置会注册到引擎下拉；采样型配置仅作为资料保存。检查文件是否包含合法的 9 参数 `engineParams`。 |
| 分析 LUT 后曲线没有变化？ | 等待“分析结果已同步”；确认输出 Gamma/Gamut 同时为 `LA - 标题`；若不是，检查文件和输入基底。 |
| 为什么我的 F-Log2C 被映射为 F-Log2？ | 工作台会保留原始文件标记，并选用原版目录中可用的标准项；应由用户根据官方资料确认此映射是否适合项目。 |
| 为什么导出的流程执行后结果不一样？ | 流程不包含素材本身，也可能依赖原版控件顺序、候选项和环境；应将输入基底、版本和用途写入流程名称。 |
| 为什么刷新后流程或配置消失？ | 本地数据保存在浏览器，可能被清理或未在当前浏览器中保存；请导出 JSON 备份。 |
| 深色模式下曲线为何仍是白底？ | 这是刻意设计，用于保证曲线对比度和可读性。 |

## 10. 建议的交付前检查表

1. 确认素材的记录 Gamma、记录 Gamut 与数据范围。
2. 确认 02 区输出目标与项目交付规范。
